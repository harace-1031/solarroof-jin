1. 이 수정 ZIP의 파일과 static 폴더 내용을 GitHub solarroof-jin 저장소 최상위에 업로드하고 Commit changes 합니다.
2. 기존 SOLAR_JIN용 Supabase 프로젝트를 그대로 사용해도 됩니다. SQL Editor에서 동봉한 검색기록표_생성.sql 전체를 실행하세요. 새 roof_building_search_events 표만 만들며 기존 기록은 변경하지 않습니다. RLS를 활성화합니다.
3. Render → solarroof-jin → Environment → 아래 세 항목을 등록합니다.
   SUPABASE_URL = https://프로젝트ID.supabase.co (기존 SOLAR_JIN과 같은 값 사용 가능)
   SUPABASE_SECRET_KEY = 같은 Supabase 프로젝트의 Secret key 또는 service_role 키
   ADMIN_PASSWORD = 직접 정한 관리자 비밀번호
   기존 BUILDING_API_KEY 등 다른 설정은 유지합니다. 비밀번호나 키는 GitHub 또는 대화창에 올리지 않습니다.
4. 저장 및 배포 후 Live를 확인합니다.
5. 실제 건물 주소를 검색하고 결과 주소를 클릭하여 위치 조회를 완료하세요.
6. https://solarroof-jin.onrender.com/admin 에서 관리자 비밀번호 입력 → 엑셀 다운로드.
   사용자 도메인 연결 후 https://solarroof.jinenergy.co.kr/admin 도 가능합니다.
7. 엑셀 열은 검색 건물주소, 검색일시(한국시간)입니다. 같은 주소를 다시 선택해 조회하면 별도 행으로 남습니다.

수집 시작은 배포·환경변수·DB표 설정을 모두 완료한 이후입니다. 이전 기록은 복구하거나 소급 생성하지 않습니다.
검색어 타이핑이나 추천 결과 전체를 수집하지 않습니다. 결과를 선택하여 /api/center 위치 조회가 성공한 건물 지번주소를 기록합니다. 도로명·건물 동명은 아직 별도로 수집하지 않습니다.
저장 실패 시 지도 사용을 막지 않으며, 관리자 다운로드에서 연결 상태를 확인할 수 있습니다. 운영 서버의 네트워크와 실제 Supabase 설정은 배포 후 검증해야 합니다.
